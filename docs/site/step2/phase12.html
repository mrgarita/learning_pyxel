1. 考え方

1-1. 公開しないものは、フォルダの外へ

pyxel package は、指定したフォルダの中身を丸ごと詰めます（step1 で学んだとおりです）。 フェーズ 11 でためしに作った step2.html の中身を取り出してみると、こうなっていました。

stages/ は、.gitignore に書いて GitHub に上げないようにしていたフォルダです。 ところが pyxel package は .gitignore を見ないので、公開する HTML の中には入ってしまいます。 その HTML を docs/site/ に置いて push すれば、隠したつもりのアイデアも一緒に公開されます。 画面には出ませんが、HTML から中身を取り出せば、だれでも読めます。

そこで、アイデア置き場は step2/ の外（リポジトリ直下の step2_ideas/）へ引っ越しました （このページを書く前に、もう済ませてあります。.gitignore も step2_ideas/ に書き換え済みです）。 公開版を作る前に毎回よけておく、というやり方もできますが、ゲームを直すたびに作り直すので、 1 回でも忘れれば入ってしまいます。最初から外に置いておけば、忘れようがありません。

大きさを見ても、気づけない ためし版の step2.html は 10,548 バイト、アイデアと一時ファイルを除いた公開版は 10,480 バイトでした。 ちがいはたった 68 バイトです。中身の確かめ方は、pyxel package を実行したときに出る 一覧を見ることです（3-3）。

ちなみに、Pyxel 2.9.9 の pyxel package のプログラムを読むと、次のものだけは自動で外れます。 それ以外は、どんなファイルでも入ります。

1-2. 1 枚の HTML を、パソコンとスマホで共用する

step1 では、パソコン版の candy_hunt.html とスマホ版の candy_hunt_mobile.html を 別々に公開しました。全画面ボタンはパソコン版にだけ付けています。 step2 はコードがはじめから両方に対応しているので、HTML は 1 枚にします。

困るのは全画面ボタンです。備忘録で調べたとおり、 スマホでは全画面ボタンを押しても反応しません（パッドが画面のタッチをすべて受け止めるため。 iPhone の Safari には、そもそもページを全画面にする機能がありません）。 付けたままスマホで開くと、こうなります。

そこで、パッドが出る端末では、全画面ボタンを隠します。 ポイントは「パッドが出る端末かどうか」をどうやって見分けるかです。 Pyxel の Web 版（pyxel.js 2.9.9）を読むと、パッドを出すかどうかは次の 1 行で決めていました。 

_isTouchDevice = () => window.matchMedia("(pointer: coarse)").matches

pointer: coarse は、「この端末で主に使う指し示す道具は、大ざっぱ（coarse）か」という問いです。 指は大ざっぱ、マウスは細かい（fine）、という分け方です。 CSS にも、同じ問いをそのまま書けます。 

@media (pointer: coarse) {
  #fs-btn { display: none; }
}

「指で触る端末なら、{ } の中の指定を使う」という意味です。 Python で書けば if 指で触る端末: ボタンを隠す にあたります。 display: none は「表示しない（場所も取らない）」です。

1-3. Web 版でも、ESC でゲームが止まる

Pyxel は、ESC キーを押すとアプリを終わらせる作りになっています（パソコンで実行するとウィンドウが閉じます）。 これが Web 版でも働きます。公開版を作ってブラウザで確かめたところ、1 面を遊んでいる途中で ESC を押すと、 画面が止まったまま、矢印キーも効かなくなりました（frame_count が 105 から進まなくなった）。 元に戻すには、ページを読み込みなおすしかありません。

全画面ボタンを付けると、「全画面から抜けるときは ESC」と覚えることになります。 ところが全画面でないときに ESC を押すと、ゲームが止まってしまいます。 押しまちがえやすいキーなので、Web で公開するゲームでは、ESC で終わらないようにしておきます。

やり方は、pyxel.init() に quit_key=pyxel.KEY_NONE を渡すだけです。 

pyxel.init(SCREEN_WIDTH, SCREEN_HEIGHT, title="Sokoban", quit_key=pyxel.KEY_NONE)
  • quit_key は「押すとアプリが終わるキー」です。書かなければ pyxel.KEY_ESCAPE（ESC）になります
  • pyxel.KEY_NONE は「どのキーでもない」という特別な値です。終わらせるキーがなくなります
  • 同じ版で ESC を押しても、ゲームは動き続け、矢印キーで歩けることを確かめました
名前を書いて渡す引数（キーワード引数） title="Sokoban" のように、名前=値 の形で渡す引数をキーワード引数といいます。 pyxel.init() の引数は width, height, title, fps, quit_key, … の順に並んでいて、 順番どおりに渡すなら fps を飛ばせません。名前を書けば、間を飛ばして、ほしいものだけを渡せます。 fps は書かないので、いつもの 30 のままです。
パソコンで実行したときは、ウィンドウの × で閉じる ESC で閉じなくなるのは、python sokoban.py で動かすときも同じです。 閉じるときは、ウィンドウの右上の × を押します。

4. うまくいかないときは

公開まわりのトラブルは、step1 フェーズ 10 と step0 フェーズ 8 の表もそのまま使えます。ここでは step2 で新しく出るものを挙げます。

症状原因と対処
pyxel package の一覧に stages や tempCodeRunnerFile.py が出る 公開版に入っています。外へ移す・消すをしてから、pyxel package からやり直します（3-2）
ブラウザで ESC を押すと、ゲームが止まって何も効かなくなる quit_key=pyxel.KEY_NONE が入っていません（3-1）。 コードを直したら、pyxel package → app2html → 置きなおし → ボタンを足し直しまで全部やり直します。 止まってしまったページは、読み込みなおせば最初から遊べます
手元のブラウザで、ボタンの文字が 蜈ｨ逕ｻ髱｢ のように化ける 2 行目の <meta charset="utf-8"> がありません（3-7）。 公開すると GitHub が「UTF-8 です」と伝えるので化けずに見えますが、手元で化けるので足しておきます
スマホ（またはデバイスモード）で、全画面ボタンが出る @media の 4 行がないか、coarse のつづりが違います（course など）。 つづりを間違えてもエラーは出ず、「指で触る端末ではない」扱いになるだけなので、見た目で気づくしかありません
デバイスモードにしたらボタンは消えたのに、パッドが出ない F5 で読み込みなおします。パッドは、ページを読み込んだ瞬間に決まります（3-8）
公開 URL を開くと 404 ① push してから数分待ったか。② 置き場所が docs/site/step2/ か。 ③ ファイル名が sokoban.html か（大文字・小文字も区別されます。Sokoban.html では開けません）
スマホで開くと、前の版が出る スマホのブラウザが前の版を覚えています。アドレスバーの再読み込みで読み込みなおします
スマホで、音が鳴らない ① 最初の TOUCH TO START をタッチしたか（これが「操作」になって音が許されます）。 ② iPhone は、消音モード（マナーモード）だと Web ページの音が鳴らないことがあります
全画面ボタンが消えた pyxel app2html をやり直したためです。足し直します（3-7）

5. step2 をふりかえる

6. 次の step

step3 は「縦スクロールシューティング」です。3 ステージ制で、中ボスとボスが出てきます。 弾幕やパワーアップアイテムもあります。step2 から大きく変わるのは、次のところです。

  • マス目から、ドット単位の動きに戻る … 1 マスずつではなく、step1 のように少しずつ動きます。 ただし、動くものの数がけた違いに増えます
  • たくさんのものを、リストで出し入れする … 弾や敵が、生まれては消えていきます。 リストを回しながら、その中身を消すときの注意が出てきます
  • 敵の出方をデータにする … 「何秒目に、どこから、どの敵が出るか」を表にします。 step2 で地図をデータにしたのと同じ考え方です
  • 角度で弾を飛ばす … 弾幕は、角度から向きを計算して作ります。 ここで初めて math.sin() と math.cos()（三角関数）を使います

フェーズ 11 で作った入力の組（INPUT_OK など）は、step3 でははじめから使い、 最初からスマホでも遊べる形で作っていきます。
