番外 ステージを四角くない形にする

外側を「描かない・通れない」にする

トップページ ／ step2 概要 ／ 四角くない形

ゴール

ここまでのステージは、ぜんぶ四角い部屋でした。 まわりを壁でぐるりと囲んで、その中で荷物を運ぶ形です。

でもオリジナルの倉庫番は四角くありません。 出入り口が飛び出していたり、通路が細く伸びていたり、 盤面の形そのものがパズルの一部になっています。

自分で作ってみた、こういう形のステージを題材にします。 

STAGE11 = [
    "....####.........",
    "....#.@#.........",
    "...##$.#######...",
    "...#..$.....O#...",
    "...#...#######...",
    "...##........O###",
    "...##############",
]
この地図は、パズルとしては完成しています 検算すると 押し 17 回 / 矢印 28 回で解けました。 荷物 2 つとゴール 2 つがどちらも内側にあり、 主人公は外に出られません（壁で密閉されている）。
直すところはパズルではなく、絵の出しかただけです。

1. いまのコードだと、どうなるか

行の長さをそろえるために、余白を .（床）で埋めています。 ところが draw_game() は「# でも O でもなければ床」と判断するので、 ステージの外側にも床タイルを描いてしまいます。

2. 考え方：地図の文字を 1 つ増やす

いままで地図に使ってきた文字は 5 つでした。ここに 6 つめを足します。

文字意味描く絵通れるか
#壁壁のタイル通れない
.床床のタイル通れる
Oゴールゴールのタイル通れる
$荷物（下は床）床＋リンゴ押せる
@主人公（下は床）床＋ワンコ—
半角スペースステージの外側何も描かない通れない

新しい文字にしてほしいことは、2 つだけです。

  1. 描かない —— draw_game() で、空白のマスは飛ばす
  2. 通れない —— 壁を調べるところで、空白も壁の仲間に入れる
「絵を描かない壁」だと考えると、かんたんです 外側は壁と同じくらい固いけれど、絵だけ描かない。 そう決めてしまえば、新しい考え方は要りません。
ほんとうは「外側」と「壁」はちがうものですが、 ゲームの動きのうえでは区別する必要がないのです。 区別しなくていいものを区別しない——これでコードが短く済みます。

2-1. 行の長さは、コードのほうでそろえる

もうひとつ問題があります。行の長さをそろえるのに、末尾を空白で埋めたくないのです。

行の末尾の空白は、エディタが消してしまいます VS Code には「保存するとき、行末の空白を取り除く」設定があり、 たいてい有効になっています。
" #### " と書いても、保存したら " ####" になってしまうのです。 そうなると行の長さがそろわず、tiles[y][x] がはみ出して IndexError になります。

なので行末の空白は書かないことにして、そろえるのはコードにやらせます。

3. このフェーズで使う機能

機能役割
max(...) いちばん大きい数を返す。max(len(row) for row in rows) で いちばん長い行の長さ
"文字列".ljust(n) 左そろえで長さを n にする。足りないぶんは右に空白が入る。 すでに n 以上なら何もしない
in "# " 「# か 半角スペース のどちらかなら」。 == "#" or == " " を短く書いた形
continue ループのいまの 1 回だけ飛ばして、次へ進む。 break（ループから出る）とはちがう
str.strip() 前後の空白を取り除く。空っぽの行かどうかを調べるのに使う

4 段階です。足すのは 6 行、書き換えるのは 2 行だけです。

STAGE11 = [     # 四角くない形。外側は半角スペース

ここでフェーズ 6 の仕込みが効きます ステージを 1 つ増やすのにやったのは、地図を書いて、STAGES に名前を 1 つ足しただけです。 「11」という数字はどこにも書いていません。
それでも画面の表示は STAGE 1/11 に変わり、11 面目を解いたら ALL CLEAR! が出ます。len(STAGES) で数えているからです （フェーズ 6 の 6-2）。 フェーズ 6 で約束したとおりになりました。

4-2. load_stage() の先頭で、行の長さをそろえる

    def load_stage(self, rows):
        """文字の地図を読んで、壁・主人公・荷物に分ける"""
        width = max(len(row) for row in rows)       # いちばん長い行に合わせる  ← 足す
        rows = [row.ljust(width) for row in rows]   # 短い行は空白で埋める      ← 足す

        self.tiles = []
        self.boxes = []
rows に代入し直していますが、もとの地図は変わりません rows = [row.ljust(width) for row in rows] は、 新しいリストを作って、rows という名札を張り替えているだけです。 STAGE11 自体は 1 文字も変わりません。
だから R でやり直しても、毎回おなじ地図から作り直せます。 もし STAGE11 の中身を書き換えるコードだったら、 2 回目から壊れていました（フェーズ 5 の「浅いコピー」と同じ話です）。

4-3. is_wall() を足して、壁を調べる 2 か所を差し替える

has_box() のすぐ手前に足します。

    def is_wall(self, x, y):
        """そのマスは通れないか。ステージの外側の空白も、壁とおなじ扱いにする"""
        return self.tiles[y][x] in "# "

    def has_box(self, x, y):
        """そのマスに荷物があるかどうかを答える"""

そして try_move() の中で == "#" と書いてある 2 か所を差し替えます。 

        if self.is_wall(next_x, next_y):        # 行き先が壁なら      ← 書き換え
            return                              # 何もしないで戻る

        if self.has_box(next_x, next_y):        # 行き先に荷物があるなら
            far_x = next_x + dx                 # 荷物の、1 つ先のマス
            far_y = next_y + dy
            if self.is_wall(far_x, far_y):      # その先が壁なら押せない  ← 書き換え
                return
2 か所を 1 か所にまとめた形です 「壁かどうか」を調べるところが 2 つあったので、答える係を 1 つ作って、両方から呼びます。 こうしておくと、あとで「氷のマスも通れない」を足したくなっても、直すのは 1 か所です。
load_stage()、draw_center()、start_game() と同じ考え方です （フェーズ 7 の 1-2）。

4-4. draw_game() で、空白のマスを飛ばす

        # 壁を、上の行から 1 マスずつ描く
        for y in range(len(self.tiles)):
            for x in range(len(self.tiles[y])):
                mark = self.tiles[y][x]
                if mark == " ":         # ステージの外側。何も描かない   ← 足す
                    continue
                if mark == "#":
                    u = U_WALL
                elif mark == "O":
                    u = U_GOAL
                else:
                    u = U_FLOOR
continue は「この 1 回だけ飛ばす」 continue に出会うと、その下を読まずに、ループの次の回に進みます。 ここでは「このマスは描かずに、次のマスへ」という意味です。
break と混ぜないように気をつけてください。 break だとループをやめてしまうので、 最初の空白より右がぜんぶ描かれなくなります。

5. 解説

5-1. 外側を「通れない」にしておく理由

STAGE11 は壁で密閉されているので、じつは外側を通れるままにしても、 今回は外に出られません。ではなぜ壁の仲間に入れるのでしょうか。

作りかけの地図で壁を 1 つ書き忘れたときのためです。 外側が通れると、ワンコはすーっと画面の外へ歩いていってしまいます。 しかもそこには絵がないので、ワンコだけが黒い空間に浮かびます。

外側を壁にしておけば、そういうときも「壁にぶつかって止まる」だけです。 おかしな地図を書いても、おかしな動きにはなりません。

5-2. ljust() が「すでに長い行には何もしない」のが効く

"##############".ljust(14) は、14 文字のまま返ってきます。 短くもならないし、エラーにもなりません。

だからいちばん長い行のことは気にせずに書けます。 7 行のうち 2 行はもともと 14 文字なので、その 2 行には何も起きません。 残り 5 行にだけ空白が足されます。

反対向きの rjust() もあります rjust() は右そろえで、空白が左に入ります。 今回それを使ってはいけません。左に空白が入ると、 地図が右にずれて壁の位置が変わってしまいます。
「ljust は left（左そろえ）」と覚えてください。

5-3. in "# " で 2 つの文字をまとめて調べる

return self.tiles[y][x] in "# "

これは、こう書くのと同じです。

mark = self.tiles[y][x]
return mark == "#" or mark == " "

"# " は「# と 半角スペース」の 2 文字が並んだ文字列で、 in は「その中にあるか」を調べます。

3 つめを足したくなったら、そのまま並べます たとえば穴のマス X も通れないことにしたいなら、 in "# X" です。ただし文字を 1 つも書き忘れないこと。
in "#" にしてしまうと空白が通れるようになり、 in " " にすると壁を通り抜けられます。

5-4. 左端にそろえて書くと、ぴったり中央に来る

盤面を画面の中央に置くのは、フェーズ 1 で書いたこの計算です。 

        board_w = len(self.tiles[0]) * TILE
        self.ox = (SCREEN_WIDTH - board_w) // 2

中央に置かれるのは「地図の四角」で、「ステージの中身」ではありません。 だから左に余分な空白を入れると、そのぶん中身が右にずれます。

地図の書きかた地図の大きさ中身の中心画面の中心からのずれ
左に空白 3 つを残す
（" ##$.#######"）		 17 × 7x = 9212 ドット右（1.5 マス）
左端にそろえる
（"##$.#######"）		 14 × 7x = 800 ドット

いちばん左に来る行を、左端にぴったり付けて書く。これだけで直ります。

コードで自動的にそろえることもできます 共通してある左の空白をコードで取り除けば、書きかたを気にしなくて済みます。 load_stage() の width を計算する手前に入れます。 やらなくても大丈夫です——書くときに気をつけるだけでも同じ結果になります。 
        indent = len(rows[0])                   # 左の空白がいくつあるかを数える
        for row in rows:
            if row.strip() != "":               # 空っぽの行は数えない
                indent = min(indent, len(row) - len(row.lstrip(" ")))
        rows = [row[indent:] for row in rows]   # その数だけ、左を切り落とす
row.lstrip(" ") は左の空白を取り除いた文字列なので、 len(row) - len(row.lstrip(" ")) が左の空白の数になります。

5-5. どこに入れるかは、手ごたえで決める

STAGE11 は押し 17 回です。 作り直した後半 4 面と並べると、こうなります。

並び面と押し回数手ごたえの変わり方
いちばん最後に置く
（..., STAGE10, STAGE11）		 … 24 → 28 → 36 → 44 → 17 ★ 最後で急に下がる。「10 面より 9 面のほうが難しい」と同じ形になってしまう
STAGE6 と STAGE7 のあいだ … 12 → 17 → 24 → 28 → 36 → 44 ◎ きれいに右肩上がり。形が変わるので、後半に入る前の切り替えにもなる

なので7 面目として入れるのがおすすめです。 地図は 1 文字も書き直しません。STAGES の並びを変えるだけです。 

STAGES = [STAGE1, STAGE2, STAGE3, STAGE4, STAGE5, STAGE6,
          STAGE11,                          # 形がちがう面を、後半に入る前に
          STAGE7, STAGE8, STAGE9, STAGE10]
「名前の番号」と「何面目か」は別ものです STAGE11 という名前でも、STAGES の 7 番目に置けば 画面には STAGE 7/11 と出ます。
何面目かを決めているのは STAGES の並びだけで、 変数の名前は関係ありません。名前は自分が見分けるためのラベルです。

7. うまくいかないときは

症状原因と対処
IndexError: string index out of range 行の長さがそろっていません。load_stage() の ljust() の 2 行を書きましたか（4-2）
外側に床タイルが出たまま draw_game() の if mark == " ": continue がありません。 または地図の余白がまだ . のままです
ステージの右半分だけ描かれない continue のところを break と書いています。 break はループをやめてしまいます（4-4）
ワンコが画面の外へ歩いていく is_wall() の中が in "#" になっていませんか。 in "# "（# のうしろに半角スペース）です
壁を通り抜けてしまう 逆に in " " になっています。# が抜けています
地図が右にずれて出る 左に余分な空白が入っています。 いちばん左に来る行を、左端にぴったり付ける（5-4）
地図が左にずれる／形がくずれる ljust() を rjust() と書いていませんか。 ljust です（5-2）
2 回目に遊ぶと形がくずれる rows[y] = ... のように地図そのものを書き換えていませんか。 rows = [...] と新しいリストを作るのが大事です（4-2）
ValueError: max() arg is an empty sequence rows が空っぽです。STAGES に 中身のないリストを入れていませんか
左上が STAGE 1/10 のまま STAGES に STAGE11 を足していません。 地図を書くだけでは増えません
解けない／リンゴがゴールに乗らない 写し間違いです。python .todo/solve.py で確かめてください （フェーズ 6 の 7-2）

8. 自分で形を作るときのコツ

気をつけることなぜ
まわりを # でぐるりと閉じる 1 か所でも開いていると、そこから外へ出られます。 外側を壁扱いにしたので出ていけませんが、地図としては間違いです
ゴールと荷物は必ず内側に置く 外側に置いても描かれないので、永久に解けない面になります
行末の空白は書かない エディタが消してしまいます。書かなくても ljust() がそろえます
いちばん左に来る行を、左端に付ける 中央にそろいます（5-4）
書けたら solve.py を走らせる 解けるかと、押し回数（＝手ごたえ）がその場でわかります
隅をゴールにしない 隅が罠として生きます。四角くない形は隅がたくさんできるので、 ここがよく効きます（番外ページの 1-1）
四角くない形は、それだけで難しくなります 細い通路や飛び出した部分は、押す向きを 1 つに決めてしまいます。 難易度のページで「通路を 1 マスにする」を レバーの 1 つに挙げましたが、四角くない形はそれを自然に作ってくれます。
今回の STAGE11 は押し 17 回で、広い部屋の面（10 × 9 で 9 回）より ずっと手ごたえがあります。盤面は狭いのに、です。
