フェーズ 1 縦長の画面に、ワンコの機体を出して動かす

機体の絵を 2 コマ描き、8 方向に動かす。画面の外へは出さない

トップページ ／ step3 概要 ／ フェーズ 1

ゴール

128×160 ドットの縦長の画面に、ワンコが乗ったプロペラ機を出します。 プロペラは 2 枚の絵を入れかえてくるくる回り、矢印キー（スマホなら十字キー）で8 方向に動きます。 ななめでも速さは同じで、画面の端まで来たら止まります。 このフェーズで書くコードは 80 行（空行とコメントを除くと 49 行）です。

このフェーズで作るファイル step3/ フォルダを作り、その中に次の 2 つを置きます。 フォルダとファイルはご自身で作ってください。 
step3/
├── shooter.py       これから書くコード
└── shooter.pyxres   リソースエディタで作る絵
ゲームの名前（ウィンドウの上に出る Wanko Sky）は仮です。タイトル画面を作るフェーズ 15 で決めなおせます。

1. 考え方

1-1. 画面を縦長にする

pyxel.init() の最初の 2 つは横の幅、縦の高さの順です。 step1・step2 は 160, 120（横長）でしたが、今回は 128, 160 と縦を長くします。 縦スクロールのシューティングでは、上から来る敵や弾が早く見えるほどよけやすくなるからです。

この大きさなら、スマホの縦向きで開いたときも、画面の下に出るパッドとゲーム画面が重なりません （step3 概要で実測）。パソコンでは、ウィンドウが縦長で開きます。 

pyxel.init(SCREEN_WIDTH, SCREEN_HEIGHT, title="Wanko Sky", quit_key=pyxel.KEY_NONE)

quit_key=pyxel.KEY_NONE は、step2 の最後に足した「ESC で終わらない」指定です （step2 フェーズ 12 の 1-3）。 Web で公開するとき困らないように、今回ははじめから入れておきます。ウィンドウはいつも右上の × で閉じます。

1-2. 機体は 16×16 を 2 コマ。まわりは黒のまま

機体の絵は 16×16 ドットです（step2 の主人公は 8×8 でした）。 プロペラが回って見えるように、プロペラだけがちがう絵を 2 枚用意して、交互に出します。

描くときの約束は 3 つです。

  1. 16×16 からはみ出さない（となりのコマに入ると、その絵が混ざって出ます）
  2. まわり（透明にしたいところ）は、黒のままにしておく。エディタの何も描いていないところは、はじめから黒です
  3. 黒く見せたいところ（目・鼻・輪郭）は、紺（色番号 1）で描く

blt() の最後に渡す色（colkey）は「この 1 色だけは描かない」という意味でした。 step2 では、主人公の目を黒で描いたら目まで透明になったので、まわりを灰色で塗って灰色を透明にしました （備忘録）。 今回はその逆で、まわりは黒のまま・黒は使わないと決めます。まわりを塗る手間がなく、 空の上では紺の輪郭のほうがやわらかく見えます。この決まりは、このあと描く敵やふうせんにも使います。 

COLKEY = pyxel.COLOR_BLACK      # 透明にする色。黒く見せたいところは紺で描く

1-3. 絵の置き場所を、先に決めておく

step2 で学んだとおり、イメージバンクのどこに描くかが、そのままコードの数字になります。 step3 は描く絵がとても多いので、大まかな区画を先に決めておきます。 このフェーズで描くのは、左上の 2 コマだけです。

1-4. 入力は、step2 の「入力の組」をそのまま使う

step2 のフェーズ 11 で、キーボードのキーとスマホのボタンを1 つのリストにまとめ、 held() で「どれか 1 つでも押されているか」を調べるようにしました。 今回はこれをはじめから使います。このフェーズで要るのは、上下左右の 4 組と held() だけです。 

INPUT_DOWN = [pyxel.KEY_DOWN, pyxel.KEY_S, pyxel.GAMEPAD1_BUTTON_DPAD_DOWN]
INPUT_UP = [pyxel.KEY_UP, pyxel.KEY_W, pyxel.GAMEPAD1_BUTTON_DPAD_UP]
INPUT_LEFT = [pyxel.KEY_LEFT, pyxel.KEY_A, pyxel.GAMEPAD1_BUTTON_DPAD_LEFT]
INPUT_RIGHT = [pyxel.KEY_RIGHT, pyxel.KEY_D, pyxel.GAMEPAD1_BUTTON_DPAD_RIGHT]


def held(inputs):
    """inputs のどれかを、押しているあいだ True を返す（btn のまとめ版）"""
    return any(pyxel.btn(i) for i in inputs)

倉庫番では、十字キーのななめ（上と右が同時）で進まないようにしました。 シューティングでは逆に、ななめにも進みたいので、2 つ同時に押されたら両方の向きに動かします。 スマホのパッドも、ななめのところを押すと 2 つのボタンが同時に押された扱いになるので、そのままななめに進めます。

1-5. まず「向き」だけを決め、あとで速さを掛ける

いきなり self.player_x -= 1.5 と書かず、どちらへ進むかを dx・dy に -1・0・1 で決めます。 速さを掛けるのはそのあとです。 

        dx = 0
        dy = 0
        if held(INPUT_LEFT):
            dx -= 1
        if held(INPUT_RIGHT):
            dx += 1
        ...
        self.player_x += dx * speed

こうしておくと、「ななめかどうか」が dx と dy を見るだけで分かります（次の 1-6）。 左と右を同時に押したときは、-1 + 1 で dx が 0 になり、どちらにも動きません。

1-6. ななめは、そのままだと速すぎる

速さを 1.5 にして、右と下を同時に押すと、1 フレームで横に 1.5、縦に 1.5 進みます。 ところが実際に動いた距離は、正方形の対角線なので約 2.12 ドット——まっすぐのときの約 1.4 倍です。 ななめに逃げるだけで速くなってしまうので、ななめのときだけ速さに 0.7 を掛けます。

0.7 はどこから来たのか 1 辺が 1 の正方形の対角線は √2（約 1.414）です。ななめの距離を 1 にもどすには、 横と縦をそれぞれ 1 ÷ 1.414 ≒ 0.707 倍にすればよい、というわけです。 ゲームでは 0.7 で十分で、10 フレームで比べると、まっすぐ 15 ドット・ななめ 14.8 ドットとほぼそろいます（実測）。

1-7. 画面の外へ出さない（min と max）

self.player_x・self.player_y は、機体の絵の左上の位置です。 左端・上端はどちらも 0 ですが、右端は 128 ではなく 128 - 16 = 112 です。 左上が 112 のとき、絵の右はしがちょうど画面の右はし（128）に来るからです。下も同じで 160 - 16 = 144 です。

「0 より小さければ 0、112 より大きければ 112」を、Python の min()（小さいほう）と max()（大きいほう）で 1 行に書きます。 読み方は 6-3 で説明します。 

        self.player_x = max(0, min(self.player_x, SCREEN_WIDTH - PLAYER_SIZE))
        self.player_y = max(0, min(self.player_y, SCREEN_HEIGHT - PLAYER_SIZE))

1-8. プロペラは、2 フレームごとに絵を入れかえる

pyxel.frame_count（起動してから何フレーム目か）を使い、コマ A を 2 フレーム → コマ B を 2 フレームとくり返します。 

        frame = pyxel.frame_count // PROPELLER_FRAMES % 2     # 0 と 1 をくり返す
frame_count01234567
// 200112233
% 2（＝ frame）00110011
出す絵AABBAABB

frame が 0 なら u = 0（コマ A）、1 なら u = 16（コマ B）です。 frame * PLAYER_SIZE でこの数が出ます。1 秒に 30 フレームなので、プロペラは 1 秒に 7〜8 回まわって見えます。

2. このフェーズで使う機能

機能使い方
pyxel.init(w, h, title=…, quit_key=…)画面を作る。横・縦の順。quit_key=pyxel.KEY_NONE で ESC で終わらない（step2 の復習）
pyxel.load("shooter.pyxres")絵を読み込む。shooter.py と同じフォルダに置く
pyxel.blt(x, y, 0, u, v, w, h, colkey)イメージバンク 0 の (u, v) から w×h を切り出して (x, y) に描く。 colkey の色は描かない。x・y は小数でもよい（備忘録）
pyxel.frame_count起動してから何フレーム目か。絵の入れかえに使う
held(inputs)自分で作った関数。リストのどれかが押されているあいだ True（step2 の復習）
min(a, b) ／ max(a, b)Python に最初からある関数。小さいほう／大きいほうを返す

3. 手順

3-1. フォルダを作り、エディタを開く

リポジトリのいちばん上に step3 フォルダを作ったら、その中で次を実行します。 

cd step3
pyxel edit shooter.pyxres

3-2. コマ A を描く

イメージバンク 0 の左上の 16×16（u=0〜15・v=0〜15）に、機体を描きます。 見本と同じでなくてかまいません。

描くときのコツ
  • いちばん上の段はプロペラ用に空けておく。ここだけをコマ B で変えます
  • 顔を大きく。16×16 でも、目・鼻・耳があればワンコに見えます。見本は柴犬ふうに、頭をオレンジ（9）、 耳を茶（4）、口のまわりを白（7）、目と鼻を紺（1）にしました
  • 羽は左右いっぱいに。横に広い形にすると、上から見た飛行機らしくなります
  • 空の水色（12）と、うすい青（6）は、機体に使わない。空にまぎれて見えなくなります
  • 黒（0）は使わない（1-2）。暗いところは紺（1）で

3-3. コマ B を作る

コマ A を範囲選択してコピーし、すぐ右（u=16）に貼り付けます（step2 で歩くアニメの 2 コマ目を作ったときと同じ）。 貼り付けたら、いちばん上の段のプロペラだけを描きかえます。見本は、横に長い羽（コマ A）と、短い羽（コマ B）です。

プロペラ以外は 1 ドットも変えない 2 枚は 2 フレームごとに入れかわります。顔や羽が 1 ドットでもずれていると、機体全体がぶるぶる震えて見えます。

3-4. 保存して閉じる

Ctrl + S で保存し、Esc でエディタを閉じます。 step3 フォルダに shooter.pyxres ができていれば完了です。

4. コード

step3/shooter.py に次を入力してください。 入力の組と held() は、step2 の sokoban.py と同じです。 

# shooter.py
# step3 フェーズ1：縦長の画面に、ワンコの機体を出して動かす

import pyxel

SCREEN_WIDTH = 128
SCREEN_HEIGHT = 160

COLKEY = pyxel.COLOR_BLACK      # 透明にする色。黒く見せたいところは紺で描く

PLAYER_SIZE = 16                # 機体の絵の大きさ（16×16）
PLAYER_SPEED = 1.5              # 1 フレームに進むドット数（小数でよい）
DIAGONAL = 0.7                  # ななめに進むときに速さに掛ける数
PROPELLER_FRAMES = 2            # プロペラの絵を何フレームごとに替えるか

# 入力の組。キーボードのキーと、スマホに出るボタン（仮想ゲームパッド）
INPUT_DOWN = [pyxel.KEY_DOWN, pyxel.KEY_S, pyxel.GAMEPAD1_BUTTON_DPAD_DOWN]
INPUT_UP = [pyxel.KEY_UP, pyxel.KEY_W, pyxel.GAMEPAD1_BUTTON_DPAD_UP]
INPUT_LEFT = [pyxel.KEY_LEFT, pyxel.KEY_A, pyxel.GAMEPAD1_BUTTON_DPAD_LEFT]
INPUT_RIGHT = [pyxel.KEY_RIGHT, pyxel.KEY_D, pyxel.GAMEPAD1_BUTTON_DPAD_RIGHT]


def held(inputs):
    """inputs のどれかを、押しているあいだ True を返す（btn のまとめ版）"""
    return any(pyxel.btn(i) for i in inputs)


class App:
    def __init__(self):
        """起動時の設定"""
        pyxel.init(SCREEN_WIDTH, SCREEN_HEIGHT, title="Wanko Sky", quit_key=pyxel.KEY_NONE)
        pyxel.load("shooter.pyxres")
        # 機体は、左右のまんなか・画面の下のほうから始める
        self.player_x = (SCREEN_WIDTH - PLAYER_SIZE) / 2
        self.player_y = SCREEN_HEIGHT - PLAYER_SIZE - 16
        pyxel.run(self.update, self.draw)

    def update(self):
        """フレーム毎の更新処理"""
        self.update_player()

    def update_player(self):
        """矢印キー（十字キー）で機体を動かす。画面の外へは出さない"""
        # まず、どちらへ進むかだけを決める（-1・0・1）
        dx = 0
        dy = 0
        if held(INPUT_LEFT):
            dx -= 1
        if held(INPUT_RIGHT):
            dx += 1
        if held(INPUT_UP):
            dy -= 1
        if held(INPUT_DOWN):
            dy += 1

        # ななめのときは、少し遅くして速さをそろえる
        speed = PLAYER_SPEED
        if dx != 0 and dy != 0:
            speed = PLAYER_SPEED * DIAGONAL

        self.player_x += dx * speed
        self.player_y += dy * speed

        # 画面の枠の中に収める
        self.player_x = max(0, min(self.player_x, SCREEN_WIDTH - PLAYER_SIZE))
        self.player_y = max(0, min(self.player_y, SCREEN_HEIGHT - PLAYER_SIZE))

    def draw(self):
        """描画処理"""
        pyxel.cls(pyxel.COLOR_CYAN)
        self.draw_player()

    def draw_player(self):
        """機体を描く。プロペラの絵 2 枚を交互に出して、回って見せる"""
        frame = pyxel.frame_count // PROPELLER_FRAMES % 2     # 0 と 1 をくり返す
        pyxel.blt(self.player_x, self.player_y, 0, frame * PLAYER_SIZE, 0,
                  PLAYER_SIZE, PLAYER_SIZE, COLKEY)


App()

6. コードの解説

6-1. dx・dy は「どちらへ」だけを持つ

dx と dy に入るのは -1・0・1 のどれかだけです。 「どれだけ進むか」は speed が受け持ち、最後に dx * speed で合わせます。 

        speed = PLAYER_SPEED
        if dx != 0 and dy != 0:
            speed = PLAYER_SPEED * DIAGONAL

「dx も dy も 0 でない」がななめです。 and を or と書くと、まっすぐのときまで遅くなってしまいます（7 で実測）。 向きと速さを分けておいたおかげで、この判断が 1 行で書けています。

6-2. 位置は小数のまま持つ

1 フレームに 1.5 ドット進むので、self.player_x は 56.0 → 57.5 → 59.0 … と小数になります。 はじめの位置も (128 - 16) / 2 で 56.0 です（/ の答えはいつも小数）。 pyxel.blt() は小数を受け取ると、いちばん近いドットに四捨五入した位置に描きます。 位置そのものは小数のまま持っておくので、1.5 ドットずつ、ちゃんと進みます（備忘録）。

6-3. max(0, min(x, 112)) は内側から読む

かっこの内側から読みます。まず min(x, 112) で「112 より大きければ 112」、 その答えを max(0, …) に渡して「0 より小さければ 0」です。

xmin(x, 112)max(0, …)意味
-1.5-1.50左へはみ出しかけた → 0 に戻す
50.050.050.0枠の中 → そのまま
113.5112112右へはみ出しかけた → 112 に戻す

min と max を逆にすると、機体が左端に張りついて動かなくなります（7 で実測）。 「上の限りは min、下の限りは max」と覚えておきます。

6-4. // と % は、左から順に計算される

pyxel.frame_count // PROPELLER_FRAMES % 2 は、// と % が同じ強さなので、左から計算されます。 つまり (frame_count // 2) % 2 です（1-8 の表）。 順番を入れかえて frame_count % 2 // 2 と書くと、答えがいつも 0 になり、プロペラが止まって見えます。

6-5. update() と draw() から、係に分けて呼ぶ

いまは機体しかないので、update() の中身は self.update_player() の 1 行だけです。 わざわざ分けたのは、このあと弾・敵・ふうせん……と係が増えていくからです。 

    def update(self):
        """フレーム毎の更新処理"""
        self.update_player()
        # フェーズ 2 から、ここに self.update_bullets() などが並んでいく

update() と draw() は「係を順に呼ぶだけの目次」にしておくと、 ゲームが大きくなっても、どこに何が書いてあるか迷いません。

7. うまくいかないときは

多くは、書きまちがいを 1 つずつ入れたコードを本物の Pyxel で動かして、症状を確かめたものです。

症状原因と対処
Exception: Failed to open file 'shooter.pyxres' shooter.pyxres が shooter.py と同じフォルダにありません。 step3 に入らずに pyxel edit すると、リポジトリのいちばん上にできてしまいます。step3 へ移してください
機体のまわりに黒い四角が出る blt() の最後の COLKEY が抜けています
目や輪郭のところだけ、空の色が透けて見える そこを黒（0）で描いています。黒は透明になるので、紺（1）で描きなおしてください（1-2）
機体がチカチカ点滅する（出たり消えたり） コマ B が見つかっていません。blt() の u と v が逆 （0, frame * PLAYER_SIZE）だと、コマ B を下の段（何も描いていない所）から切り出し、 2 フレームおきに消えます。コマ B を u=16 以外に描いたときも同じです
機体がぶるぶる震える コマ A と B で、プロペラ以外のドットがずれています（3-3）
プロペラが回らない frame_count % PROPELLER_FRAMES // 2 と、// と % の順番が逆です（1-8）。 コマ A と B が同じ絵のときも回りません
右端（または下端）まで行くと、機体が画面から消える min(self.player_x, SCREEN_WIDTH) と、- PLAYER_SIZE が抜けています。 左上が 128 まで行けてしまい、絵がまるごと画面の外に出ます
起動すると左端に張りついて、左右に動かない min(0, max(…)) と、min と max が逆です（1-7）。答えがいつも 0 になります
まっすぐ進むのが遅い（ななめと同じくらい） if dx != 0 or dy != 0: と、and が or になっています。10 フレームで 15 ドット進むはずが 10.5 ドットでした
ななめだけ速い ななめのときに DIAGONAL を掛けていません。10 フレームで縦横 15 ドットずつ（約 21 ドット）進みます
↓ を押すと上へ行く if held(INPUT_DOWN): の下が dy -= 1 になっています。下は += 1 です（y は下が大きい）
押した瞬間に少し動くだけで、押しっぱなしでは進まない held() の中が pyxel.btnp になっています。btnp は押した瞬間だけ True です。pyxel.btn にします
